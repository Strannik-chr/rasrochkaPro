# ARCHITECTURE.md — Архитектура системы «РассрочкаПро»

## 1. Обзор и выбор стека в текущем окружении
В соответствии с п. 1 и п. 3 Технического задания был проведён аудит существующего рабочего пространства:
- В репозитории развёрнут проект на базе **Node.js v22.23.4 + TypeScript + Express + React 19 + Vite + Tailwind CSS**.
- Среда исполнения контейнера предоставляет встроенный реляционный движок **SQLite (`node:sqlite` DatabaseSync)** с поддержкой ACID-транзакций, внешних ключей и строгих ограничений, а также подготовлена полная схема миграций **PostgreSQL (`migrations/001_init_postgres.sql`)** и конфигурация **Docker Compose** для автономного production-развёртывания.
- Отказ от сноса существующего React/TypeScript/Express-рантайма в пользу переписывания среды выполнения обоснован в `DECISIONS.md` (ADR-001): модульный монолит реализован с тем же строгим разделением слоёв (Handlers → Services/Domain → Repositories → Relational DB), которое требуется для промышленной разработки.

```text
/

├── migrations/                  # Версионируемые SQL-миграции (PostgreSQL и SQLite)

├── src/
│   ├── shared/                  # Общие типы DTO, константы ролей и статусов
│   │   └── types.ts
│   ├── server/                  # Backend: модульный монолит
│   │   ├── config/              # Валидация переменных окружения и параметров безопасности

│   │   ├── finance/             # Централизованный финансовый движок (целые копейки, без float)
│   │   ├── security/            # Argon2/Scrypt хеширование, сессии, CSRF, TOTP MFA, Rate Limiter
│   │   ├── audit/               # Неизменяемый журнал аудита (append-only)
│   │   └── routes/              # Модульные REST API обработчики (auth, clients, suppliers, purchases, contracts, payments, finance, documents, reports, settings, users)

```

## 3. Слой бизнес-логики и транзакций
- **Финансовое ядро (`src/server/finance/calculator.ts`)**: чистые детерминированные функции расчёта полной себестоимости, наценки, первоначального взноса, генерации графика с тремя режимами округления и четырёх моделей досрочного погашения.
- **Транзакционный контур (`BEGIN IMMEDIATE` / `COMMIT` / `ROLLBACK`)**:
  - Оформление договора атомарно создаёт запись договора, фиксирует версию настроек, создаёт версию №1 графика платежей, при наличии первоначального взноса регистрирует платёж, кассовую операцию и запись аудита.
  - Распределение платежа атомарно проверяет `Idempotency-Key`, остаток нераспределённых средств, обновляет строки графика, пересчитывает статус договора (`active` / `completed`) и записывает аудит.
  - Сторнирование денежной операции не удаляет исходную строку, а помечает её как `reversed` и создаёт зеркальную компенсирующую проводку с обязательной причиной.
